# VRCX Route Difference Register

This register maps every page currently shipped by the root Next.js application to its authoritative VRCX source and records visible or behavioral differences that still matter. “Maintained” means the route has an implemented, working remote/browser-backed slice; it does not mean matched-pixel parity is proven. Detailed persistence and observation semantics remain in [`PLANS.md`](../PLANS.md).

The inventory source is `src/app/**/page.tsx`. Route groups such as `(authenticated)` do not contribute a URL segment. The production navigation source is [`src/components/app-shell.tsx`](../src/components/app-shell.tsx); `/settings` and `/about` are reached from its Manage and Help menus rather than the primary list.

## Verification meaning

- Current-port deterministic captures prove only the states explicitly recorded in `PLANS.md`; they do not substitute for a running-VRCX comparison.
- “Matched comparison remains open” means the route must not be counted as exact visual parity even if its unit tests and build pass.
- Any added or removed `page.tsx` must update the shipped-route table. An automated test compares this table with the filesystem inventory.
- Every newly accepted difference must also update `PLANS.md` when it changes eligibility, persistence, monitoring semantics or product behavior.
